# Draft PDF compiled in the browser
Compile the paper to a real elsarticle PDF inside the browser (BusyTeX WASM, MIT upstream) so authors see the final layout while editing, without a server.
Branch: feat/browser-pdf. Delivery: auto-chain, feature-branch-chain (slices on feat/browser-pdf, one merge to main at the end; forecast ~1500 authored lines); push/PR/merge/deploy are the user's decision. Runner: `npm test` (Vitest) in web/; checks `npx tsc --noEmit`, `npx eslint src`, `npm run build`.

## Specs
- S1. "podemos superar el problema de compilacion del pdf para que vean el pdf como sale al final? (pero en menor calidad) en vez de que el html no conserve las propor ciones?" The workspace can show a draft PDF built in the browser with the same LaTeX class as CI (elsarticle via the Quarto elsevier format), so line breaks, page breaks and float positions follow TeX. It is labelled as a draft; the CI PDF stays the official one. The instant HTML preview stays.
- S2. "joe prefiero ver si podemos hacerlo client side..." Compilation runs entirely in the browser (Web Worker + WASM); no galley server or third-party compile service.
- S3. "pues, mejor probar la MIT no? por si acaso se convierte en producto". Only MIT-compatible code is vendored or bundled: upstream busytex/busytex (MIT scripts; TeX Live binaries under their own free licenses), not texlyre-busytex (AGPL-3.0). Attribution and licenses ship with the assets.
- S4. galley's own renderer emits the LaTeX (no pandoc.wasm): front matter (title, authors, affiliations, abstract, keywords, journal highlights and options from `format.elsevier-pdf`), includes, numbered sections with labels, `\appendix`, figures, tables, display/inline math with labels, cross-references (`@sec-`/`@fig-`/`@tbl-`/`@eq-` → `\ref`), citations through natbib + BibTeX with the elsarticle bst. Reference: `web/src/render/fixtures/quarto-elsevier-reference.tex` (Quarto 1.9 + pandoc 3.9 output for the fixture paper). The HTML preview output stays unchanged.
- S5. Engine assets come from a pinned upstream busytex WASM release (TeX Live 2023), verified by SHA-256, trimmed to a subset that compiles the Quarto elsevier template and common packages; every file under GitHub Pages' 100 MB limit; downloaded only when the draft PDF is first requested and then cached by the browser. Known upstream bugs fixed in the vendored pipeline: argv array reused across passes, and "enable all data packages" when a conditional package is unresolved.
- S6. A long-lived compile worker keeps the engine loaded between compiles; its own time budget (not the 5 s HTML budget); Recompile / Ctrl+Enter / auto-compile drive it like the preview; TeX errors are shown as readable notes; missing packages or unsupported content give a clear note instead of a broken PDF.
- S7. Security: TeX runs with `--no-shell-escape` inside the WASM sandbox; CSP gains only what WASM needs (`'wasm-unsafe-eval'` in `script-src`), pinned by `csp.test.ts`; the PDF is shown as an `application/pdf` blob like the CI PDF view.
- S8. English and Spanish copy; README documents the feature, its limits and the asset build.
